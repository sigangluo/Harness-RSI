### APE

| 字段 | 内容 |
|---|---|
| 标题 | Large Language Models Are Human-Level Prompt Engineers |
| 机构 | University of Toronto; Vector Institute; University of Waterloo |
| 摘要 | 通过基于自然语言指令进行条件生成，大语言模型（LLM）已展现出作为通用计算机的惊人能力。然而，任务性能在很大程度上取决于用于引导模型的提示的质量，而大多数有效的提示都是由人工手写的。受经典程序综合以及人类进行提示工程方式的启发，我们提出了自动提示工程师（Automatic Prompt Engineer，APE），用于自动生成和选择指令。在我们的方法中，我们将指令视为"程序"，通过在由LLM提出的一组指令候选中进行搜索，以最大化所选定的评分函数来对其进行优化。为评估所选指令的质量，我们评估另一个LLM在遵循该指令时的零样本表现。大量实验表明，我们自动生成的指令在24/24条指令归纳（Instruction Induction）任务和17/21条经过筛选的BIG-Bench任务上，大幅超越了此前的LLM基线，并达到或优于人工标注者生成的指令。我们进行了广泛的定性与定量分析，以探究APE的性能。我们展示了APE生成的提示能够提升少样本学习性能（只需将其加在标准上下文学习提示之前）、找到更好的零样本思维链提示，以及引导模型趋向真实性和/或信息量。 |
| 代码 | https://github.com/keirp/automatic_prompt_engineer |
| 对比方法 | Human（人工撰写指令）；Greedy（Honovich et al., 2022提出的无搜索/选择过程的模型生成指令算法） |

| 机构 | Cognizant AI Labs；American University；University of Cambridge & CarperAI；Autodesk Research；New Jersey Institute of Technology；CarperAI |
| 摘要 | 语言模型天然地支持一种智能变异算子，其精神与进化交叉（crossover）相似。具体而言，具有足够规模的语言模型展现出上下文学习能力，即能够从少量输入模式之间的关联中学习，从而生成融合了这些关联的输出（也称少样本提示）。这一能力可以被用来构建一种变异算子：即用少量基于文本的基因型（如代码、纯文本句子或方程）对语言模型进行提示，并将其相应的输出解析为这些基因型的后代。这种语言模型交叉（实现简单，且可利用许多不同的开源语言模型）的前景在于：它使得以很少的领域特定调整来演化语义丰富的文本表示成为可能，并能自然地受益于语言模型当前的进步。本文的实验通过对二进制位串、句子、方程、文本到图像提示以及Python代码的演化，凸显了语言模型交叉方法的多样性。结论是：语言模型交叉是一种灵活且有效的方法，可用于演化任何可表示为文本的基因组。 |
| 代码 | 论文正文声明将公开配套实现代码但未在文中给出具体链接；经检索确认公开仓库为 https://github.com/jal278/lmx（置信度中等） |

### ProTeGi

| 字段 | 内容 |
|---|---|
| 标题 | Automatic Prompt Optimization with "Gradient Descent" and Beam Search |
| 机构 | Microsoft Azure AI |
| 摘要 | 大语言模型（LLM）作为通用智能体已展现出令人瞩目的性能，但其能力仍高度依赖于提示，而提示的编写通常需要繁琐的试错过程，由人工手写完成。我们提出了一种简单的非参数化解决方案——文本梯度提示优化（Prompt Optimization with Textual Gradients，ProTeGi），其灵感来自数值梯度下降，用于在假设可以访问训练数据和LLM API的前提下自动改进提示。该算法使用小批量数据形成对当前提示进行批评的自然语言"梯度"，这与数值梯度指向误差上升方向的方式类似。随后，这些自然语言梯度通过在梯度的语义反方向上编辑提示而被"传播"回提示中。这些梯度下降步骤由一种束搜索和赌博机（bandit）选择流程引导，从而显著提升算法效率。在三个基准NLP任务以及一个新颖的LLM越狱（jailbreak）检测问题上的初步结果表明，自动提示优化能够超越此前的提示编辑技术，通过利用数据将模糊的任务描述改写为更精确的标注说明，将初始提示的性能提升多达31%。 |
| 代码 | https://github.com/microsoft/LMOps/tree/main/prompt_optimization |
| 对比方法 | Monte-Carlo (MC，对应APE式蒙特卡洛搜索，Zhou et al., 2022)；Reinforcement Learning (RL，代表GrIPS/TEMPERA式短语级搜索)；AutoGPT；进化式搜索+均匀带宽选择（对应GPS, Xu et al., 2022） |

### LATM

| 标题 | Large Language Models as Tool Makers |
| 机构 | Google DeepMind; Princeton University; Stanford University |
| 摘要 | 近期研究表明，借助合适的外部工具，大语言模型（LLM）有潜力提升其问题求解能力。在本工作中，我们进一步推进这一理念，提出一个闭环框架，称为"LLM作为工具制造者"（LATM），其中LLM为问题求解创造自己可复用的工具。我们的方法包含两个阶段：1）工具制造：一个LLM充当工具制造者，为一组任务打造工具，工具以Python实用函数的形式实现；2）工具使用：另一个LLM充当工具使用者，应用工具制造者构建的工具进行问题求解。工具使用者可以与工具制造者是同一个LLM，也可以是不同的LLM。在问题求解服务端，工具制造使得工具能够随新请求出现而持续生成并缓存。该框架使后续请求能够通过相应的API访问已缓存的工具，从而提高任务解决的效率。除了使LLM能够创造自己的工具外，我们的框架还揭示了优化LLM服务成本的有趣机会：鉴于工具制造需要更复杂的能力，我们将此任务分配给强大但资源消耗较大的模型；相反，较简单的工具使用阶段则交由轻量级模型完成。这种策略性的分工使得一次性的工具制造成本可以分摊到多个工具使用实例上，在保持强劲性能的同时显著降低平均成本。 |

| 标题 | Large Language Models as Optimizers |
| 机构 | Google DeepMind |
| 摘要 | 优化在各处无处不在。尽管基于导数的算法已经是解决各种问题的强大工具，但梯度的缺失给许多现实世界的应用带来了挑战。在本工作中，我们提出了通过提示进行优化（Optimization by PROmpting，OPRO），一种简单而有效的方法，利用大语言模型（LLM）作为优化器，其中优化任务用自然语言描述。在每个优化步骤中，LLM根据包含此前生成的解及其取值的提示生成新的解，随后对新解进行评估并将其加入提示以用于下一个优化步骤。我们首先在线性回归和旅行商问题上展示了OPRO，随后转向我们的主要应用——提示优化，其目标是找到能够最大化任务准确率的指令。通过多种LLM的实验，我们证明由OPRO优化得到的最佳提示在GSM8K上比人工设计的提示高出多达8%，在Big-Bench Hard任务上高出多达50%。 |

| 对比方法 | Zero-shot CoT "Let's think step by step"（Kojima et al., 2022）；APE生成指令（Zhou et al., 2022b）；空字符串基线；线性回归/TSP案例研究中与传统启发式算法/精确求解器比较 |

| 对比方法 | Chain-of-Thought (CoT)；Vanilla/External（人工提供工具）；LATM、CREATOR（其他工具创建方法）；SimCSE、BM25（替代检索方式） |

### STOP

| 字段 | 内容 |
|---|---|
| 标题 | Self-Taught Optimizer (STOP): Recursively Self-Improving Code Generation |
| 机构 | Stanford University; Microsoft Research; OpenAI |
| 摘要 | 近期AI系统的若干进展通过提供一个"脚手架"程序来解决问题，该程序组织对语言模型（LM）的多次调用以生成更好的输出。在本工作中，我们使用一个融合了语言模型的脚手架程序来改进它自身。我们从一个种子"改进器"（improver）开始，它根据给定的效用函数通过多次查询LM并返回最佳方案来改进输入程序。然后我们运行这个种子改进器来改进它自己。在一小组下游任务上，改进后的改进器生成的程序性能显著优于其种子改进器。语言模型提出了多种自我改进策略，包括束搜索、遗传算法和模拟退火。由于语言模型本身没有被改变，这并非完全的递归自我改进。尽管如此，这表明现代语言模型（本实验中为GPT-4）能够编写调用自身以实现自我改进的代码。 |
| 代码 | https://github.com/microsoft/stop |
| 对比方法 | Chain-of-Thought baseline（种子改进器仅做一次改进）；Greedy iterative improver；跨模型对比（GPT-4、GPT-3.5、Mixtral作为基座） |
